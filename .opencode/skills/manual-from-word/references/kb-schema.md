# data/kb.json 字段与写作规范

## 整体结构

```json
{
  "title": "存量房网签备案系统 · 操作答疑",
  "subtitle": "依据《存量房网签备案系统操作手册》整理",
  "disclaimer": "页面底部免责说明",
  "roles": [{ "id": "org", "name": "经纪机构", "dir": "jg", "manual": "经纪机构版操作手册" }],
  "entries": [ /* 答疑条目 */ ],
  "gaps": [ /* 手册缺口 */ ]
}
```

| 字段 | 说明 |
|---|---|
| `title` | 页面左上大标题，一般 `系统名 · 操作答疑` |
| `subtitle` | 副标题，写依据哪本手册 |
| `disclaimer` | 底部说明，写明“手册没写的不会编答案” |
| `roles[].id` | 角色标识，`entries[].roles` 引用它 |
| `roles[].name` | 角色中文名（页面切换按钮上的字） |
| `roles[].dir` | 截图目录名 = 文件名前缀，`jg` → `screenshots/jg/jg_01.jpg` |
| `roles[].manual` | 该角色对应的手册名，方便排查对图 |

单本手册只定义 1 个角色（页面自动隐藏角色切换条）；多本手册按册定义多个角色。

## entries（答疑条目）

```json
{
  "id": "kb-001",
  "roles": ["org", "hall"],
  "module": "系统登录",
  "title": "系统用什么浏览器？页面显示不正常怎么办？",
  "answer": "推荐使用谷歌浏览器、360 浏览器（极速模式）、Edge 浏览器……",
  "steps": ["第一步点哪里", "第二步填什么"],
  "note": "注意事项（只写手册明确写的限制）",
  "source": "第一章 1.1 系统登录",
  "kw": ["浏览器", "360", "IE"],
  "hot": true,
  "shots": { "org": [1], "hall": [1] }
}
```

| 字段 | 规则 |
|---|---|
| `id` | `<sys>-001` 递增，不重复；删条目后不要回填旧号 |
| `roles` | 手册里确实提到该角色才写；多角色时判断依据是手册对应分册 |
| `module` | 用手册章节标题，不要自创；同一模块内条目顺序跟着手册 |
| `title` | **用户口吻的疑问句**，带口语词（怎么、能不能、哪里、为什么），一句话 ≤ 30 字 |
| `answer` | 结论先行，2~4 句；第一句直接回答“能/不能/在哪点”，不要复述提问 |
| `steps` | 3~6 步，每步一个动作，动词开头，保留原按钮名（【新增】）；纯概念题可为空数组 |
| `note` | 只放手册白纸黑字写的限制/例外；没有就空字符串 |
| `source` | `第X章 X.X 小节名`，多本手册用 `/` 分隔（如 `第五章 5.1 合同签约 / 第三章 3.2 合同签约`） |
| `kw` | 3~6 个检索关键词：按钮名、菜单名、业务词、常见错别字 |
| `hot` | 每个模块挑 1 条最常被问的设为 `true`，全系统 4~8 条 |
| `shots` | `{ 角色id: [图片序号...] }`；序号取自 `manual/图片清单.txt`；对不上就不写 |

### 写作禁忌

- 不要把手册的“功能介绍段落”整段抄进 `answer`，要改写成“你该点哪里”
- 不要写政策口径（申请条件、收费标准、办理时限），那是 `gaps`
- 不要出现“如下图所示”“见下图”这类依赖图片才能懂的句子
- 不要用“用户可以……”的第三人称，直接说“点【新增】”

## gaps（手册缺口）

```json
{ "topic": "申请条件与材料清单", "risk": "高", "detail": "手册只讲系统怎么录入，没写准入条件、收入标准、必交材料。", "owner": "" }
```

| 字段 | 规则 |
|---|---|
| `topic` | 短话题名（≤ 15 字），能被检索命中 |
| `risk` | `高` = 上线首周大概率被问 / `中` = 会被问但频率低 |
| `detail` | 说明“手册哪一块没有”“用户为什么会问”，一至两句 |
| `owner` | 留给业务方填负责部门，初始空串 |

缺口来源：手册里出现“按系统提示操作”“详见线下规定”“具体以政策为准”这类模糊表述；
章节标题存在但没有操作细节；页面截图里出现但正文没讲的按钮。
一般一本手册整理 10~18 条。
